# codeassistant — LLM context summary

## What this project is
A local, offline AI code assistant. It runs a multi-agent ReAct (Reason + Act) loop powered entirely by Ollama. An orchestrator classifies each user task and delegates it to a specialist agent (coder or general). Each agent reasons step-by-step and calls tools until the task is done. No external APIs required except Ollama running at localhost:11434.

## Entry points
- `python agent.py` — REPL, defaults to orchestrator agent
- `python agent.py "task"` — single-shot
- `python agent.py --agent coder|general|orchestrator "task"` — force agent
- `python agent.py --model <name>` — override model for all agents
- `python agent.py --cwd /path "task"` — set working directory
- `python agent.py --no-stream "task"` — disable streaming output
- `./run.sh` — wrapper that invokes .venv/bin/python agent.py
- `./preload_models.sh` — warm all unique agent models into Ollama memory in parallel before starting the agent; respects ORCHESTRATOR_MODEL / CODER_MODEL / etc. env overrides; `--unload` releases all models

## Key files
- `agent.py` — argparse CLI, instantiates agent, calls run() or repl()

- `agents/general.py` — open-ended ReAct with all tools
- `agents/__init__.py` — REGISTRY dict mapping name → class
- `tools/registry.py` — TOOLS list (schemas) + execute_tool() dispatcher
- `tools/file_ops.py` — read_file, write_file, edit_file, list_dir
- `tools/bash_exec.py` — safe shell execution; tracks cwd via `pwd` append
- `tools/code_nav.py` — grep_code, find_files, code_outline, read_lines

- `tools/snippets.py` — persistent code snippet store (filesystem)

## Streaming
LLM output streams token-by-token by default in both REPL and single-shot modes.
- `llm.chat()` accepts `on_chunk(chunk: str)` callback; when provided it enables Ollama streaming mode
- `BaseAgent._call_llm()` wraps the call: Rich builds a `Live(transient=True)` panel that fills as tokens arrive and disappears cleanly when done; plain-terminal fallback prints inline
- `BaseAgent._streaming` bool (default from `STREAM_OUTPUT` config); propagated to all sub-agents
- Disable: `--no-stream` CLI flag or `STREAM_OUTPUT=false` env var

## Config (config.py) — env vars and defaults
- OLLAMA_BASE_URL=http://localhost:11434
- AGENT_MODEL=qwen2.5-coder:3b  (global fallback)
- AGENT_MODELS (Preset A — balanced, ~7.3 GB, 16 GB RAM / 8 cores target):
    orchestrator=qwen2.5:0.5b, coder=qwen2.5-coder:7b, lint=qwen2.5-coder:7b,
    planner=phi4-mini:3.8b, general=phi4-mini:3.8b
  (override with ORCHESTRATOR_MODEL, CODER_MODEL, LINT_MODEL, PLANNER_MODEL, GENERAL_MODEL env vars)
- AGENT_MAX_ITER=15 (max ReAct iterations per run)
- LLM_TIMEOUT=600 (seconds; 7b+ models need 5-10 min on CPU for complex first responses)
- STREAM_OUTPUT=true (stream tokens in real time; set to false to disable)
- BASH_TIMEOUT=60 (seconds per shell command; also used by lint runner and git ops)
- RAG_FETCH_TIMEOUT=30 (seconds for rag_add_url HTTP fetch)
- EMBED_MODEL=qwen3-embedding:4b
- RAG_CHUNK_SIZE=600, RAG_CHUNK_OVERLAP=80

## Agent hierarchy
OrchestratorAgent → (routes via fast LLM call) → PlannerAgent | CoderAgent | LintAgent | GeneralAgent
Any depth-0 agent can delegate a sub-task to another agent via delegate_to_agent tool.
Delegation is capped at depth=1 to prevent recursion.

## BaseAgent (agents/base.py) — the parent class
All agents inherit from BaseAgent. Key attributes:
- name: str — used for AGENT_MODELS lookup
- model: resolved from _model_override or AGENT_MODELS[name]
- _model_override: raw --model arg; None = use per-agent config; propagated to sub-agents
- cwd: str — current working directory, mutated by bash and change_dir tools
- _depth: int — delegation depth (0 = top-level, 1 = delegated sub-agent)

Abstract method subclasses must implement:
- build_system_prompt() -> str — the full system prompt injected at position 0 each iteration

Optional override:
- handle_special_action(action, action_input) -> str | None
  Called before execute_tool(). Return an observation string to continue the loop, or None
  to fall through to the tool registry. ALWAYS call super().handle_special_action() for
  unknown actions so delegation continues to work in subclasses.

ReAct loop (run method):
1. Build messages = [system_prompt, user_message]
2. Loop up to MAX_ITERATIONS:
   a. llm.chat(messages) → raw string
   b. _extract_action(raw) → dict | None (searches for ```json block, falls back to first {})
   c. If None (no JSON): if looks like prose/code and misses<=2, inject correction and retry;
      else treat as final answer and return.
   d. If action == "final_answer": print answer, return.
   e. Call handle_special_action(action, action_input).
      - "delegate_to_agent": spawn sub-agent, run task, return result as observation.
      - "plan" (CoderAgent): display plan, return acknowledgement.
      - None: fall through to execute_tool.
   f. execute_tool(action, action_input, cwd) → (result_str, new_cwd)
   g. Append "Observation: <result>" to messages, update cwd, continue.

JSON-enforcement retry: when a model returns prose instead of JSON (detected by presence of
``` or "def " or "import " or "class "), the loop injects a correction message asking for
JSON format and retries, up to 2 times. This prevents small models from silently skipping
the ReAct loop.

Tool docs: _tool_docs(names?) renders TOOLS into markdown. Sub-agents (depth>=1) have
delegate_to_agent stripped from their docs to prevent recursive chains.

## PlannerAgent (agents/planner.py)
Produces a structured implementation plan without writing any code. Read-only access to
the codebase; only allowed write is saving the plan document itself.
1. UNDERSTAND — restate the task, define acceptance criteria and scope
2. EXPLORE — map relevant files, symbols, patterns with read-only tools
3. ANALYZE — identify gaps, dependencies, risks, constraints, complexity
4. DRAFT — compose a full plan: steps, files table, interfaces, risks, complexity estimate
5. REPORT — write_file to save plan_<slug>.md, then final_answer with the full content
Model override: PLANNER_MODEL env var.

## LintAgent (agents/lint.py)
Enforces a 5-phase lint workflow via system prompt:
1. DISCOVER — find files/dirs to lint (find_files, list_dir, git_status, git_diff)
2. LINT — run linter on each target, collect all issues before fixing
3. FIX — edit_file / write_file / fix_code; fix errors first, then warnings, then style
4. VERIFY — re-lint every touched file; must be error-free before reporting
5. REPORT — final_answer with per-file issue counts, fixes made, and remaining warnings
Rules enforced: never edit without reading flagged lines first, no `# noqa` silencing unless
task explicitly allows it, do not call final_answer until errors = 0.
Model override: LINT_MODEL env var.

## CoderAgent (agents/coder.py)
Enforces a 5-phase workflow via system prompt and special action handling:
1. EXPLORE — read-only: list_dir, find_files, grep_code, code_outline, read_file, git_status
2. PLAN — emits {action:"plan", action_input:{summary,steps,files_create,files_modify}}
   handle_special_action displays the plan and returns acknowledgement, then IMPLEMENT begins
3. IMPLEMENT — write_file, edit_file, bash; lint after each file
4. VERIFY — lint all changed files, run_tests if suite exists, git_status
5. REPORT — final_answer with structured summary (changes, what was done, verification)
Rules enforced in system prompt: never write before reading, one tool per response,
do NOT call final_answer until all planned files are written to disk.

## GeneralAgent (agents/general.py)
Open-ended ReAct with all tools. System prompt instructs to:
- Use write_file when a task produces content to persist (code, docs, reports)
- Use delegate_to_agent for sub-tasks that fit coder or general specialty
- Save reusable patterns with save_snippet
- Documentation indexing workflow: when asked to update/index/refresh docs for a library,
  use websearch to find the official URL, then rag_add_url(collection="docs") for each key
  page (getting started, API reference, changelog). Re-ingesting a URL auto-refreshes it.
  The "docs" collection is shared with all agents — coder/lint/planner query it during EXPLORE.

## OrchestratorAgent (agents/orchestrator.py)
Does not run its own ReAct loop. Instead:
1. _keyword_route(words) pre-check — deterministic fast path for unambiguous signals:
   docs/documentation/ingest/rag → general
   lint/flake8/ruff/pylint/eslint/mypy → lint
   plan/spec/blueprint/architecture → planner
   what/how/why/explain/summarize → general
2. If no keyword match: calls llm.chat with ORCHESTRATOR_MODEL (fast, small model) for a single token response
3. Parses the response to get agent name; falls back to _keyword_route again if LLM returns unexpected output
4. Instantiates the chosen sub-agent with model=self._model_override, cwd=self.cwd, streaming=self._streaming
5. Runs the sub-agent, persists updated cwd for the next REPL turn

## Tool registry (tools/registry.py)
TOOLS: list of dicts with keys name, description, parameters (dict of param→type description).
execute_tool(name, params, cwd) -> (result_str, new_cwd): large if/elif dispatch.
Returns "Unknown tool: <name>" for unrecognised actions (reached only if handle_special_action
returned None for that action).

## Adding a new agent — checklist
1. Create agents/myagent.py, inherit BaseAgent, set name/label/border_color, implement build_system_prompt()
2. Register in agents/__init__.py REGISTRY
3. Add "myagent" entry to AGENT_MODELS in config.py
4. Add routing description to _AGENT_DESCRIPTIONS in agents/orchestrator.py

## Adding a new tool — checklist
1. Implement function in tools/*.py returning a string
2. Add definition dict to TOOLS list in tools/registry.py
3. Add elif branch to execute_tool() in tools/registry.py
Tool appears automatically in all agents' _tool_docs() output.

## Adding a special action — checklist
Override handle_special_action in your agent class. Handle your action, return observation string.
Call super().handle_special_action(action, action_input) for all other actions.
