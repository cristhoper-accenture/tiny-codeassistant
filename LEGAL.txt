4. WHY GPL-3.0 (COPYLEFT) AND NOT A PERMISSIVE LICENSE
--------------------------------------------------------------------------------

Copyleft is chosen deliberately over permissive licenses (MIT, Apache 2.0)
for the following reasons:

  a) RECIPROCITY: Anyone who distributes a modified version of this software —
     whether as source, binary, or a hosted service using AGPL terms — must
     release their modifications under the same license. This ensures the
     community always has access to improvements.

  b) PATENT PROTECTION: GPL-3.0 includes an explicit patent non-aggression
     clause (section 11). Contributors cannot later assert patent claims
     against users of the software. This is particularly relevant given the
     active patent landscape around AI tooling.

  c) AI AUTHORSHIP ALIGNMENT: Since no individual or company holds a strong
     copyright claim over AI-generated code, a copyleft license reflects the
     spirit of the work being a shared, community resource rather than
     proprietary software.

  d) ANTI-ENCLOSURE: A permissive license would allow any party to take this
     code, add proprietary modifications, and redistribute it as closed-source
     software. GPL-3.0 prevents that.

  e) TIVOISATION PROTECTION: GPL-3.0 section 6 prohibits hardware-level
     restrictions that prevent users from running modified versions
     ("anti-tivoisation"), ensuring full software freedom at every layer.

Note on network use: GPL-3.0 does NOT require source disclosure when running
the software as a network service (only distribution triggers copyleft). If
that obligation is desired, GNU AGPL-3.0 is the appropriate upgrade. Consider
switching to AGPL-3.0 if this tool is ever exposed as a web or API service.
